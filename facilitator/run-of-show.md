# McNeese AI Harnesses: two-hour run of show

Audience: faculty and staff beginners. Delivery: guided demo, with optional setup and practice. Primary outcome: participants can describe an AI harness, scope a useful task, inspect a proposed change, and decide whether the result is good enough to use.

| Minute | Segment | Observable check |
| --- | --- | --- |
| 0-10 | Welcome and show the guide. Poll for tool and Git familiarity; reassure observers that installation is optional. | Everyone can open the handout. |
| 10-25 | Three modes of AI help: chat, completion, and a harness operating on project files. Show the permission and human-review loop. | Participants can identify what the tool can see and change. |
| 25-45 | Demonstrate a small, sanitized faculty/staff task. First ask the harness to inspect, explain, and propose a plan, without editing. | Audience can state the requested output and success criterion. |
| 45-65 | Let the harness make one bounded change. Show the diff or before/after, run or inspect the output, and reject one plausible but weak suggestion. | Audience sees a human verification decision, not just generation. |
| 65-75 | Break; optional setup help. | Observers remain able to follow without accounts or installs. |
| 75-95 | Repeat the same task in the second harness, or show the equivalent workflow. Compare shared concepts rather than speed or model rankings. | Participants can translate the workflow between Codex and Claude Code. |
| 95-110 | Prompt repair exercise: turn a vague request into goal, context, boundaries, and a check. Invite participants to try it in their own tool or on paper. | Each participant has one concrete prompt they could reuse. |
| 110-120 | Debrief, optional setup paths, institutional data rules, and one next task. | Exit ticket: what changed, how would you verify it, and what must remain under human control? |

## Demo preparation

Use a synthetic, non-sensitive folder. Keep a known-good copy and a pre-recorded fallback. Before the session, test the exact task in both tools, network access, screen readability, and a clean reset. Never screen-share a personal vault, student files, emails, or live credentials. If a tool fails, narrate the same inspect, scope, act, verify loop using the prepared before/after files.

The precise main task remains an audience choice. A staff-friendly default is revising a one-page event checklist with a missing approval step; a code variant is a tiny CSV summary script. Do not commit to a Python-heavy lab unless the audience asks for it.
