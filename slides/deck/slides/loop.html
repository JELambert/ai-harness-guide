The loop we will run twice

Scope, inspect, act, verify, decide

Scope

Name the files, the goal, and what would make it wrong.

Inspect

Have it explain what is there before it writes.

Act

One bounded change, shown as a diff.

Verify

Counts, a source check, one value by hand.

Decide

Keep, revise, or reject. That part is yours.

If you cannot say what would make the answer wrong, the task is not scoped yet.

Both demos follow this loop step by step, and the slides will show which step we are on. The failure-condition line is the most useful habit in the whole session.
